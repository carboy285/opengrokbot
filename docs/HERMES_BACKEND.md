# Hermes Agent backend investigation

OpenGrokBot currently runs a selected CLI for each bot. It does not yet run Hermes Agent. Existing bot records, messages, local files, schedules and provider settings must be retained when a Hermes backend is added.

The upstream Hermes Agent project supports macOS and native Windows and can route to multiple model providers. Its current `hermes -z` / `--oneshot` entry point is not suitable for this app: `hermes_cli/oneshot.py` sets `HERMES_YOLO_MODE=1` and `HERMES_ACCEPT_HOOKS=1`, bypassing dangerous-command and hook approvals. Passing a prompt as a command-line argument would also expose it to local process inspection. Do not invoke that entry point as the bot backend.

A proper integration needs a separately launched Hermes runtime using its lower-level agent APIs, with messages sent over a private local channel, explicit approval requests delivered to the user, and cancellation that stops the underlying work. Keep a stable, separate Hermes identity and session store per bot; make provider credentials and tool access explicit rather than copying private credentials or claiming a profile is an OS security sandbox. Preserve OpenGrokBot chat history and do not silently replace existing provider settings. Hermes and OpenGrokBot scheduling must not run the same routine twice.

Upstream commit `45219aa35c2b3538192cdff448eefb3d0facd89a` provides a promising alternative to the one-shot CLI: its authenticated local gateway supports `POST /v1/runs`, streamed run events, approval responses, and stop requests. Its run requests accept a session identifier and an idempotency key. Investigate using this interface for both desktop hosts, with the phone continuing to use the existing remote-host protocol. Validate the gateway's profile-specific memory and credentials before claiming per-bot isolation; a separate conversation session alone does not establish isolated memory. The gateway also needs a private local key and lifecycle management, and approvals need an actual user interface before tools can be enabled.

Before switching existing bots, verify the integration against a pinned Hermes version on macOS and Windows, including installation, authentication, per-bot memory and sessions, concurrent requests, approvals, cancellation, failure recovery, local/remote clients, and migration of existing data. A missing or incompatible Hermes installation must result in a clear setup state, not an implicit fallback to another runtime.
